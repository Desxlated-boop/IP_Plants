# IP_Plants — Сервис учета домашних коллекций растений

## Назначение

Приложение для учета домашних растений, графика полива и журнала поливов. Есть консольная версия и веб-интерфейс на Django.

## Целевая аудитория

Любители комнатных растений, начинающие садоводы, люди, которые хотят систематизировать уход за своими цветами.

## Предметная область

Домашнее цветоводство: коллекция растений, их владельцы, места в доме (с разным освещением) и история поливов.

## Основные функции

- просмотр коллекции растений, добавление растения, поиск по названию;
- определение растений, которые пора поливать сегодня;
- отметка полива с записью в журнал (дата последнего полива обновляется);
- учет владельцев и мест, просмотр растений владельца и места;
- хранение данных между запусками в JSON;
- веб-интерфейс: списки и карточки растений, владельцев, мест, журнал и карточки поливов.

## Объектная модель (ООП)

Четыре класса пакета `models/`:

```text
Owner  <──  Plant  ──>  Location
              ^
              │
         WateringLog
```

| Класс | Атрибуты | Методы |
|-------|----------|--------|
| `Owner` | `id`, `name`, `email` | `from_data()` (classmethod), `__str__()` |
| `Location` | `id`, `name`, `light` | `validate_light()` (staticmethod), `from_data()`, `__str__()` |
| `Plant` | `id`, `name`, `species`, `interval_days`, `last_watered`, `owner`, `location` | `needs_watering()`, `days_since_watering()`, `next_watering_date()`, `water()`, `__str__()` |
| `WateringLog` | `id`, `plant`, `watered_on`, `note` | `__str__()` |

**Взаимодействие объектов:** `Plant` хранит ссылки на `Owner` и `Location` (композиция), `WateringLog` хранит ссылку на `Plant`. Функция `add_watering()` создает запись журнала и обновляет `Plant.last_watered`.

Функции работы с коллекциями (`add_plant`, `find_plant`, `find_plant_by_id`, `get_plants_needing_water`, `filter_plants_by_owner`, `filter_plants_by_location`, `add_owner`, `add_location`, `find_waterings_for_plant`, ...) лежат рядом с классами и принимают `List[...]` объектов.

## Хранение данных

Каталог `data/`: `owners.json`, `locations.json`, `plants.json`, `waterings.json`. Связи хранятся как идентификаторы (`owner_id`, `location_id`, `plant_id`). При загрузке (`storage.load_all`) JSON преобразуется в объекты, ссылки восстанавливаются; при сохранении объекты преобразуются обратно в данные. Некорректные записи пропускаются с сообщением, отсутствующий или поврежденный файл не приводит к аварийному завершению.

## Веб-интерфейс (Django 5.2)

| URL | Имя маршрута | Что показывает |
|-----|--------------|----------------|
| `/` | `homepage:index` | главная, сводка по коллекции |
| `/plants/` | `plants:list` | список растений |
| `/plants/thirsty/` | `plants:thirsty` | кого пора поливать |
| `/plants/<id>/` | `plants:detail` | карточка растения, владелец, место, история поливов |
| `/owners/` | `owners:list` | владельцы |
| `/owners/<id>/` | `owners:detail` | владелец и его растения |
| `/locations/` | `locations:list` | места |
| `/locations/<id>/` | `locations:detail` | место и растения в нем |
| `/waterings/` | `waterings:list` | журнал поливов |
| `/waterings/<id>/` | `waterings:detail` | отдельная запись о поливе, растение, владелец, место и заметка |

Для несуществующих объектов страницы возвращают код 404; для неизвестных адресов настроен `handler404`.

**Шаблоны Django:** базовый `templates/base.html` (блоки `title`, `content`), наследование `{% extends %}`, включаемые шаблоны (`includes/navigation.html`, `plants/includes/plant_card.html`, `plants/includes/watering_status.html`), контекст из view-функций, `{% for %}…{% empty %}`, `{% if %}`, фильтры (`length`, `default`, `date`), именованные URL с пространствами имён, статические файлы (`homepage/static/homepage/`: `css/style.css`, `js/main.js`, `img/logo.png`), Bootstrap 5.3 через CDN.

Основные Django-страницы получают данные через ORM из `db.sqlite3`.
Консольная версия использует JSON, а учебные SQL-страницы ПР7 читают
отдельную базу `data/plants.sqlite`. Автоматической синхронизации между этими
источниками нет. Django-формы пользовательского интерфейса пока не созданы.

## ПР9–ПР10: модели Django и админка

Модели `Owner`, `Location`, `Plant` и `WateringLog` описаны в приложениях
`owners`, `locations`, `plants` и `waterings`. Миграции создают отдельные
таблицы Django в `db.sqlite3`. Для переноса данных из базы ПР7 предусмотрена
команда `python manage.py import_pr7`: она читает `data/plants.sqlite` и
сохраняет идентификаторы и связи. Импорт выполняется в транзакции и отменяется,
если таблицы моделей Django уже содержат данные.

Основные страницы используют ORM; журнал поливов поддерживает фильтры,
сортировку и постраничный вывод. В `/admin/` зарегистрированы все четыре
модели: доступны поиск, фильтры, списки и редактирование, в карточке растения
видны связанные поливы. Для растений предусмотрены текстовый адрес,
вычисляемый базой признак редкого полива и массовые действия; статистика
ORM доступна на `/plants/statistics/`. Django Debug Toolbar доступен при
`DEBUG=True` на локальном сервере. Учётные данные администратора создаются командой
`python manage.py createsuperuser`. Админка работает с базой Django;
старые JSON-файлы и база ПР7 не обновляются автоматически.
Для просмотра текущей статистики следует использовать раздел «Статистика ORM»;
раздел «База и статистика» сохранён для SQL-запросов ПР7 и показывает снимок
из `data/plants.sqlite`. Файлы `data/*.json` и `data/*.sqlite` не включены в
Git: при настройке на другом компьютере нужны исходные JSON-файлы, затем
импорт ПР7 и `import_pr7`. Содержимое локальной `db.sqlite3` не переносится
в составе этого изменения.

## ПР7: SQLite и SQL

База коллекции `data/plants.sqlite` отделена от `db.sqlite3`, используемой
настройками Django. Структура создаётся командами `sql/schema.sql`:

| Таблица | Поля |
|---------|------|
| owners | `id INTEGER` (первичный ключ), `name TEXT`, `email TEXT` |
| locations | `id INTEGER` (первичный ключ), `name TEXT`, `light TEXT` |
| plants | `id INTEGER` (первичный ключ), `name TEXT`, `species TEXT`, `interval_days INTEGER`, `last_watered TEXT`, `owner_id INTEGER`, `location_id INTEGER` |
| waterings | `id INTEGER` (первичный ключ), `plant_id INTEGER`, `watered_on TEXT`, `note TEXT` |

`plants.owner_id` и `plants.location_id` ссылаются на владельца и место;
`waterings.plant_id` ссылается на растение. Проверка внешних ключей включается
в `db/database.py`. Даты хранятся строками в формате `YYYY-MM-DD`.

Для начального импорта из JSON выполните `python -m db.import_json`.
Скрипт создаёт таблицы и переносит данные одной транзакцией. Повторный импорт
в непустую базу отменяется, чтобы не перезаписать существующие записи.
JSON остаётся отдельным источником: после его изменения SQLite автоматически
не обновляется. Файл SQLite не добавляется в Git.

В `sql/queries.sql` находятся именованные запросы для каталогов, поиска
полива на дату и по освещению, связанных данных, подсчётов, группировки,
HAVING и LIMIT/OFFSET. Параметры передаются через `?`, результаты доступны
по именам полей благодаря `sqlite3.Row`. Страница `/plants/database/`
получает данные непосредственно из SQLite и показывает каталог, журнал,
поиск по дате и статистику. Отдельные страницы: `/plants/database/plants/`,
`/plants/database/waterings/`, `/plants/database/search/` и
`/plants/database/statistics/`. Основные страницы теперь используют ORM.
При отсутствии базы выполните импорт; Django ORM не применяется к этой базе.

Веб-страницы используют схему «представление → контекст → шаблон → HTML».
HTML в `views.py` не формируется, функция `page()` не используется.
В журнале и карточке полива повторно подключается
`plants/includes/watering_status.html` с параметром `plant=log.plant`.
Он показывает текущую потребность растения в поливе, а не состояние старой записи.
Записи журнала доступны также из истории поливов на странице растения.
В JSON и базе ПР7 даты хранятся строками `YYYY-MM-DD`, а в ORM — как даты Django.
Фильтр `date` применяется к объектам даты: на странице «Пора поливать»
и к датам последнего и следующего полива в карточке растения.

## Соответствие ПР6

Примеры методички адаптированы к теме домашней коллекции растений:
помещение соответствует растению, пользователь — владельцу,
бронирование — записи о поливе. Статус «Пора поливать / Полив не нужен»
вычисляется существующим методом `Plant.needs_watering()`.

| Требование | Где посмотреть |
|------------|----------------|
| Общая структура, блоки `title` и `content` | `templates/base.html` |
| Наследование `extends` | главная и все страницы списков и объектов |
| Навигация через `include` | `templates/includes/navigation.html` |
| Повторяемые карточки и статус | `plants/templates/plants/includes/` |
| Контекст, циклы, условия и пустые списки | `views.py` и шаблоны приложений |
| Именованные URL и пространства имён | `app_name` и `name` в `urls.py`, тег `url` в шаблонах |
| Фильтры `length`, `default`, `date` | списки, карточки и страница «Пора поливать» |
| Собственные CSS, изображение, JavaScript | `homepage/static/homepage/`, подключение в `base.html` |
| Небольшая функция JavaScript | текущий год в подвале страницы |
| Пять основных страниц | `/`, `/plants/`, `/plants/<id>/`, `/waterings/`, `/waterings/<id>/` |
| Обработка отсутствующего объекта | условие в шаблоне и HTTP-статус 404 во view |
| Сохранение предыдущих работ | `main.py`, `models/`, `storage.py`, JSON-файлы |

Для ручной проверки откройте `/plants/1/`, `/waterings/1/`,
а затем `/plants/999999/` и `/waterings/999999/`.
Несуществующие объекты должны показывать понятное сообщение и возвращать 404.
Общая страница `templates/404.html` для неизвестного адреса используется
при `DEBUG = False`; для ошибок поиска конкретного объекта это не требуется.

Материалы Яндекс Практикума и «Блогикум» выполняются отдельно в учебном курсе.
Их прохождение нельзя подтвердить наличием кода в этом проекте.
Отчёт и устная защита также выполняются отдельно.

## Запуск

```text
pip install -r requirements.txt
python main.py                 # консольная версия
python -m db.import_json       # один раз: создать базу ПР7 из JSON
python manage.py migrate
python manage.py import_pr7    # один раз, для пустых таблиц Django
python manage.py runserver     # веб-версия: http://127.0.0.1:8000/
```
