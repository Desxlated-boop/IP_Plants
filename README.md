# IP_Plants — Сервис учета домашних коллекций растений

## Назначение
Консольное приложение для ведения учета домашних растений, отслеживания графика полива и поиска растений по коллекции.

## Целевая аудитория
Любители комнатных растений, начинающие садоводы, люди, которые хотят систематизировать уход за своими цветами.

## Предметная область
Домашнее цветоводство. Учет микроклимата, графиков ухода и состава домашней коллекции растений.

## Объектная модель (ООП)
В рамках ПР3 основные сущности предметной области были переведены из словарей в полноценные классы.

### Класс `Plant` (Растение)
Объект класса `Plant` представляет собой отдельное растение в коллекции.
**Основные атрибуты:**
- `id` (int) — уникальный идентификатор растения.
- `name` (str) — название растения (например, "Фикус").
- `species` (str) — биологический вид (например, "Ficus").
- `interval_days` (int) — рекомендуемый интервал полива в днях.
- `last_watered` (str) — дата последнего полива в формате ГГГГ-ММ-ДД.

**Основные методы:**
- `__init__()` — конструктор, инициализирующий атрибуты объекта при создании.
- `needs_watering(current_date)` — метод экземпляра, который вычисляет количество прошедших дней и возвращает `True`, если растению требуется полив.
- `__str__()` — магический метод, возвращающий удобное строковое представление объекта для вывода в консоль.

**Взаимодействие объектов:**
Объекты `Plant` хранятся в коллекции `List[Plant]`. Функции модуля `plants.py` (например, `find_plant`, `get_plants_needing_water`) принимают эту коллекцию и работают с атрибутами и методами каждого объекта, не дублируя логику внутри функций.

## Хранение данных
Данные приложения сохраняются между запусками в формате JSON.
- **Файл:** `data/plants.json`
- **Формат:** Список словарей. При загрузке из JSON словари преобразуются в объекты `Plant` через конструктор. При сохранении объекты `Plant` обратно распаковываются в словари для записи в файл.
